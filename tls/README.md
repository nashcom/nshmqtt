# tls/

Everything in this directory except this file is generated by
[`../gen-cert.sh`](../gen-cert.sh) and gitignored -- run it once from the
project root:

```bash
./gen-cert.sh
```

That writes:

| File        | What it is                                    | Regenerated on every run? |
|-------------|------------------------------------------------|----------------------------|
| `ca.key`    | Local test CA private key                       | No -- created once, reused |
| `ca.crt`    | Local test CA certificate                        | No -- created once, reused |
| `tls.key`   | Leaf private key                                 | Yes -- fresh every run     |
| `tls.crt`   | Leaf certificate, signed by `ca.crt`, covering both TLS listeners (HTTPS and MQTT/TLS) | Yes -- fresh every run |

The CA is only created once (and reused on later runs) because
regenerating it would invalidate every client that already trusts the
old `ca.crt`. The leaf is cheap to regenerate and only this stack itself
needs to trust it.

`ca.crt` (never `ca.key`) is what any client needs in its own trust
store to validate a TLS connection to this stack -- `curl --cacert`,
`mosquitto_pub`/`mosquitto_sub --cafile`, or a browser/OS trust store for
a manual check. See the main [README](../README.md#tls) for the full
picture (which listeners get TLS, how `docker-compose.yml` and
`nginx/nginx.conf` use these files, and why this is server-side only).

Defaults to `localhost` (the leaf's CN and SAN), but already supports a
real hostname:

```bash
TLS_HOST=mqtt.example.com ./gen-cert.sh
```

puts `mqtt.example.com` in the CN and SAN alongside `nginx`/`localhost`/
`127.0.0.1`, so local testing keeps working either way. Not yet wired
into `docker-compose.yml` or NGINX's `server_name` -- that's the next
step once there's an actual hostname to deploy against, not something
this local setup needs today.

**Not for production.** This is a local test CA with an unencrypted
private key on disk, meant to get a working TLS setup running locally
with one command. A real deployment wants a certificate from a real CA
(e.g. via ACME) instead -- and should never generate or store that CA's
own private key this casually.

**Nothing under this directory except this file is meant to be
committed** -- see the project's `.gitignore` (`tls/*` with
`!tls/README.md`). If a *real* CA or certificate ever ends up here by
accident, that's a signal to rotate it, not just delete the file.
